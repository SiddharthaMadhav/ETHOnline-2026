The problem

Advertising infers interest by watching people.

Today's ad platforms build permanent behavioral profiles from browsing history and clicks to guess what a user might want — a model that trades user privacy for targeting accuracy, and still guesses wrong most of the time.

02

The Hark model

Platforms publish temporary intent. Agents pay for relevant reach.

A platform tells Hark what a user appears to want right now — nothing permanent, nothing identifying. Autonomous advertiser agents evaluate relevance themselves and pay only when it's worth it.

Off-chain

Intent, campaigns, matching, and relevance reasoning all live in Hark's API and database — never on-chain.

On-chain

Only x402 payment settlement touches Hedera: the advertiser pays HBAR, Blocky402 verifies and settles it.

No API key

POST /v1/reach is consumable by any advertiser agent via x402 alone — no Hark subscription required.

04

Privacy boundary

The advertiser buys reach, not identity.

Advertiser agents see

Publisher identity & placement · topic · sanitized semantic summary · confidence · price · expiration.

Advertiser agents never see

Name, email, phone, IP · wallet address · publisher's internal user ID · raw browsing history or conversation · any stable cross-platform identifier.

06

Live & shipped

What's actually running, right now.

  • Publisher creates a temporary intent from vague natural language ("something lightweight for college coding") via an LLM classifier
  • Advertiser agent discovers the anonymous opportunity and scores relevance with its own LLM call
  • Unpaid POST /v1/reach returns a real HTTP 402 with x402 payment requirements
  • Agent signs and retries automatically; Blocky402 settles a real HBAR payment on Hedera testnet
  • Delivery is queued and the ad appears on the live Demo Publisher feed
  • Bonus, shipped: HCS audit trail, HCS-14 advertiser identity, publisher revenue share
